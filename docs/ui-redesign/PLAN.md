# 구현 순서

1. route/DOM/API 조사, 임시 checkout baseline tests, 실제 template의 synthetic before 캡처.
2. 단일 토큰 계층과 Guided Screening shell, 시작/식별/검사 선택의 실제 config 경로·오류.
3. 기존 문진 payload 보존, 준비된 capability만 plan에 포함, 촬영 상태·업로드·분석 안내.
4. 결과/이력/PDF/모바일·Clinical Operations/Research 화면, plan 검토·고급 기능 접근.
5. 기존 suite 비교, 실제 Chromium interaction/viewport/상태 테스트, after 캡처와 직접 PNG 검토.
6. 기능표 재확인, 결과/rollback/handoff/README 작성, 지정 경로만 stage하여 로컬 commit.

기존 framework(Flask/Jinja/vanilla JS), endpoint·payload·분류·threshold·provider routing을 유지한다.
페이지별 점진 적용으로 기존 DOM/event를 남기며 inline 색상 token 중복을 공통 token으로 추출한다.
외부 참고 사이트 재열람 없이 팩의 명시 설계 목표를 적용한다. 타사 자산/코드를 도입하지 않는다.
